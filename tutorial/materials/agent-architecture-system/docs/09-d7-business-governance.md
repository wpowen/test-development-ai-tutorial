# 09 D7 业务治理层：Agent 版本是四维的

## 9.0 给完全没接触过的人

传统软件问"你部署的是哪个版本"，答案是一个 git commit。

Agent 不是。同一个"模型名"下，可能因为提示词改了一句、工具清单加了一个、记忆库刷新了一次，行为就完全不同。**模型名没变，系统已经变了。**

## 9.1 四个维度

| 编号 | 维度 | 判据形状 |
| --- | --- | --- |
| D7-1 | 业务规则与决策正确性 | **硬规则违反 = 0** |
| D7-2 | 合规与审计证据链 | 每个动作可追溯到「哪个 Agent、代表哪个用户、依据什么」 |
| D7-3 | **变更治理** | 模型/prompt/工具/记忆**任一变更**均触发对应回归 |
| D7-4 | 业务价值与 ROI | 与人工基线对比的效率提升 |

## 9.2 D7-3 四维版本

```text
Agent 版本 = f(模型版本, system prompt 版本, 工具清单版本, 记忆库快照)
```

- **任一维度变化都要触发回归**
- **回归基线必须锁定同一 judge 版本**（否则你在比较两把不同的尺子）

### 最常见的事故链

```text
模型供应商静默更新
   → 所有历史评估数据失去可比性
   → 团队浑然不觉，继续用旧基线做发布决定
```

### 对策：哨兵集

每个模型端点**每周跑一次哨兵集**：20–30 条确定性强的任务，分布突变即告警。

哨兵集的设计要求：

```text
□ 任务确定性强（答案唯一或不变量明确），否则分布本身就在抖
□ 覆盖高危切片
□ 规模小到可以每周跑，成本可忽略
□ 结果只用于「有没有变」，不用于「好不好」
```

**哨兵集是唯一能发现静默更新的手段。** 没有它，你只能等到某次业务事故才发现模型换了。

## 9.3 D7-2 审计证据链

监管场景的硬要求。每次工具调用需记录：

```text
执行的 Agent      : agent-refund@v3
委托的用户        : user-1042（以及委托是怎么获得的）
调用的工具        : refund_order
依据              : policy-v7#R12 + order O-77 状态快照
结果              : 成功 / 拒绝 / 错误
时间戳            : <ISO8601>
```

**既是合规要求，也是事故取证的生命线。** 出事时能不能说清"是谁、代表谁、依据什么做了这件事"，决定了事故是可归因的还是不可归因的。

### 时间线参考（来源观测）

| 法规 | 时间 | 量级 |
| --- | --- | --- |
| EU AI Act 高危义务 | 2026 年 8 月生效 | 罚则最高 3500 万欧元量级 |
| Colorado AI Act | 2026 年 6 月起可执行 | — |

相关框架：NIST AI RMF、ISO/IEC 42001、EU AI Act Art.14（人类监督）/ Art.15（网络安全）。

> ⚠ 合规判定不在测试开发的职权范围。本层的作用是**让证据存在且可取**，具体适用性由法务与合规 owner 判定。

## 9.4 D7-1 业务规则

硬规则违反 = 0 是**硬红线**，不参与统计门禁。

区分两类：

| 类别 | 例子 | 判定 |
| --- | --- | --- |
| **硬规则** | 已发货订单不得取消；退款不得超过实付 | 违反 = 阻断，无例外 |
| **软偏好** | 回复应当简洁友好 | 进统计门禁，可用分数表达 |

**常见错误**：把硬规则写成 rubric 里的一条打分项。那样它会被平均分稀释掉。

## 9.5 D7-4 ROI 的诚实算法

```text
✗ 错误: 「Agent 处理一个工单只要 30 秒，人工要 5 分钟，效率提升 10 倍」
✓ 正确: 与人工基线在同一任务集上对照，并计入：
         - 人工复核成本（有多少比例需要人看）
         - 返工成本（做错的比例 × 修复成本）
         - 逃逸成本（漏到用户侧的比例 × 影响）
         - 评估基础设施成本
         - 未验证收益单列为 UNKNOWN
```

**不能用"节省时间"直接推导 ROI**，因为节省的时间可能被复核和返工吃掉。

## 9.6 常见反模式

| 反模式 | 后果 | 正确做法 |
| --- | --- | --- |
| 用模型名当版本 | 静默更新无法察觉 | 四维版本 + 哨兵集 |
| 换 judge 后沿用旧基线 | 在比较两把不同的尺子 | 基线锁定 judge 版本 |
| 硬规则写成打分项 | 被平均分稀释 | 硬规则进硬红线 |
| 用模型自评批准 waiver | 绕过责任 | 发布 owner 署名 |
| 用节省时间直接算 ROI | 高估收益 | 计入复核、返工、逃逸、评估成本 |

## 9.8 证据边界

法规生效时间与罚则量级为**来源观测**，适用性判定属法务与合规 owner，不属测试开发。
四维版本与哨兵集是**工程综合（Inference）**。
你的系统的 ROI 为 `UNKNOWN`，必须用同任务集人工基线实测。

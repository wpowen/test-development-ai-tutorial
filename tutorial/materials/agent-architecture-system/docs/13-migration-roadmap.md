# 13 迁移路线图：P0 止血 → P4 常态化

## 13.1 五个阶段

| 阶段 | 周期（占位） | 交付 | 为什么是这个顺序 |
| --- | --- | --- | --- |
| **P0 止血** | `<4 周>` | D0-1 judge 校准<br>D5-1 / D5-2 注入投毒套件<br>D5-6 高危动作清单 | 这三项决定「现有数据可不可信」和「最坏能坏到什么程度」，必须最先做 |
| **P1 换范式** | `<6 周>` | D4-1 `pass^k` 改造<br>D1-3 span 级轨迹评估<br>环 2 沙箱回放 | 把测量方法从单点改成分布，这是后续所有工作的地基 |
| **P2 补盲区** | `<8 周>` | D2 编排全套<br>D3-3 人机协同<br>D6-2 成本经济学 | 补上一代体系完全没有的面 |
| **P3 上闭环** | `<8 周>` | 环 3 影子灰度<br>环 4 在线持续<br>D7-3 变更治理 | 从「发布前保证」转为「运行时保证」 |
| **P4 常态化** | 持续 | 红队常态化<br>judge 定期重校准<br>失败模式库 | 让它变成日常，而不是一次专项 |

## 13.2 如果只能做一件事

**先做 D0-1（judge 校准）。**

你现在所有的评估数字，准确性上限都取决于那个 judge 有多准——而这件事大概率还没有被量化过。

在 κ 未知的情况下做 P1 的 `pass^k` 改造，你会得到一个精确计算出来的、基于不可信输入的分布。

## 13.3 每阶段的准出

不满足准出就不进下一阶段。延期比跳过便宜。

### P0 准出

```text
□ 有一张填完的 Judge Card（含 κ、位置/冗长/自偏好三类偏置、停用条件、owner）
□ 人人一致性已测，且 κ_human ≥ κ_judge（否则先改 rubric）
□ 注入与投毒套件能跑，且报告区分「模型拒绝」与「授权层拒绝」
□ 高危动作清单完成三维标签（可逆性 × 影响面 × 资金影响）
□ 「不可逆 + 资金无上限」的动作已列出，对应控制已存在或已立项
```

### P1 准出

```text
□ 同一份 raw run ledger 能同时算出 pass@k 与 pass^k，且口径写明
□ 区间以任务为聚类单位计算，不是 n×k
□ 样本量不足时输出 EVIDENCE-INSUFFICIENT，而不是通过
□ span 台账能给出首错位置分布
□ 环 2 沙箱回放能跑完并产出 receipt
```

### P2 准出

```text
□ 每条 handoff 边有 schema 与 owner
□ 信息衰减链路测试有存活数结果
□ 三重熔断各注入一次并真的触发
□ 中断测试在写操作前后各做一次
□ 成本 P99 与单位成功成本进入报表
```

### P3 准出

```text
□ 影子模式验证过「新版确实不生效」（零副作用断言）
□ 影子期覆盖一个完整业务周期
□ 在线采样使用与开发阶段相同的评估器
□ 高危动作按已批准 capture policy 记录，任何已知漏记均进入 blocker
□ 四维版本 lineage 完整，任一维变更触发对应回归
□ 哨兵集已配置并跑过至少一个周期
```

### P4 准出

```text
□ 红队有固定节奏与新增攻击面的接收流程
□ judge 重校准是日程事件，不是想起来才做
□ 失败模式库在增长，且每条有护栏覆盖状态
```

## 13.4 常见的顺序错误

| 错误顺序 | 后果 |
| --- | --- |
| 先做 D6 性能优化 | 优化了一个不知道对不对的系统 |
| 先做 D2 多 Agent 编排 | 单体轨迹都看不清，编排失败无法归因 |
| 先上环 4 在线监控 | 用未校准的 judge 打分，产生大量假告警后被关掉 |
| 先做 D7 ROI 测算 | 基线不可信，数字无意义 |
| P0 只做 judge 不做安全 | 知道数据准不准，但不知道最坏能坏到什么程度 |

## 13.5 失败信号

出现即需要复盘，不要硬推：

```text
⚠ judge κ 一直没测过，但已经在用分数做发布决定
⚠ 报告里只有 pass@k，从来没有 pass^k
⚠ 攻击集只有直接注入，没有间接注入
⚠ 熔断"配置了"但从未验证过会触发
⚠ 高危动作的限额写在 system prompt 里
⚠ 上线后没有任何持续评估，靠工单发现问题
⚠ 模型供应商更新后，没有任何机制能发现
```

每一条对应一个具体的补救动作，见各域文档的"常见反模式"表。

## 13.6 证据边界

阶段周期为**结构占位**，取决于团队规模、系统复杂度与现有基础。
本路线图为**工程综合（Inference）**，未在任何真实组织落地验证；落地后的实际耗时与效果为 `UNKNOWN`。

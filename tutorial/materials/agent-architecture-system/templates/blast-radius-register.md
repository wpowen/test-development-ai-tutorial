# 爆炸半径登记册

对每个可执行动作打三维标签，再由标签组合决定强制控制。

## 三维标签

```
可逆性   : 可撤销 / 有窗口期可撤 / 不可逆
影响面   : 单用户 / 多用户 / 全平台
资金影响 : 无 / 有上限 / 无上限
```

## 登记表

| 动作 | 工具名 | 可逆性 | 影响面 | 资金影响 | 强制控制 | 控制所在层 | 已验证 | owner |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | tool / prompt | 是/否 | |

## 控制矩阵（按组合）

| 组合 | 强制控制 |
| --- | --- |
| **不可逆 + 资金无上限** | 人工确认 + 双人复核 + 单笔额度硬上限 + Kill Switch |
| 不可逆 + 有上限 | 人工确认 + 额度硬上限 |
| 有窗口期可撤 + 多用户 | 人工确认 + 撤销演练 + 影响面预览 |
| 可撤销 + 单用户 + 无资金 | 常规门禁 |

## 验证要求（最关键的一条）

**这三道控制本身要被测试，而不只是测 Agent 会不会调用。**

```
✗ 测「Agent 在这个场景下没有调用高危工具」  —— 测的是模型服从性
✓ 测「即使调用了，也会被限额/审批拦下」      —— 测的是控制有效性
```

服从性在提示注入下可被击穿；控制不会。

## 自查

- [ ] 每个动作都有三维标签
- [ ] `控制所在层` 列没有 `prompt`（限额必须在工具层）
- [ ] 每条控制都有「已验证」记录（绕过模型直接调用工具，看拦不拦）
- [ ] 边界值已测（恰好等于上限、略超上限）
- [ ] 批量动作有影响面预览（"本次将影响 N 个对象"）
- [ ] Kill Switch 触发后在途动作确实停止且不留脏状态

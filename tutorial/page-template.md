# 职业 AI 教程页面模板

## 页面顶部

每页顶部显示：课程位置、页面标题、预计时间、页面类型、难度、交付状态、更新时间和前置页面。

开头只承诺一个学习结果，例如：“完成本页后，你可以让一条错误退款承诺在 CI 中稳定失败。”不要承诺“全面掌握 RAG 评测”。

## 通俗解释

先用一句话解释，再给职业类比，然后才出现技术术语。

推荐顺序：

1. 这是什么；
2. 为什么测试开发需要它；
3. 用一个熟悉的工作类比；
4. 展示最小结构或流程；
5. 给一个正确例子和一个反例；
6. 解释本页只覆盖到哪里。

概念页不能只列名词；必须让用户能够用自己的话解释，并知道何时使用。

## 自己动手

跟做页依次提供：

- 已准备好的输入；
- 操作目录或界面位置；
- 可复制命令；
- 每一步的预期输出；
- 故障注入；
- 失败报告；
- 修复或 reset；
- 最终产物位置。

如果需要 API Key，先提供不依赖凭证的离线路径。插图或界面不能代替真实运行证据。

## 完成检查

学习者必须完成一个可观察检查：选择、预测、运行、找错、解释、修改或迁移。仅仅“阅读完毕”不算完成。

跟做页至少检查：

- 正常输入是否得到预期结果；
- 有意义的故障是否使检查失败；
- 修复后是否重新通过；
- 学员能否指出证据；
- 是否能迁移到相邻业务对象。

页面底部提供上一页、下一页和推荐复习页。

## 证据边界

每个已交付页面都要说明：

- 本页已经实际验证了什么；
- 哪些结论来自官方文档或职业资料；
- 哪些只是公开从业信号或课程策略推断；
- 哪些真实环境、学习效果或生产结果尚未验证；
- 页面状态为何是 planned、desk-researched、fixture-tested、live-tested 或 practitioner-reviewed。

不能把代码片段存在、仓库有 Stars、厂商页面有指标或离线 fixture 通过写成生产效果。

## 五类页面差异

- 概念页：一句话解释、类比、结构、最小例子、反例、小测；
- 跟做页：输入、步骤、命令、预期、故障、修复、产物；
- 诊断页：症状、检查顺序、根因、误区、修复验证、升级边界；
- 参考页：定义表、决策规则、版本、限制、替代和来源；
- 项目页：业务简报、交付物、评分、迁移挑战和人工评审。

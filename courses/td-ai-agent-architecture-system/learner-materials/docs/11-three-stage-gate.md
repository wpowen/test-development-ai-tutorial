# 11 三段式门禁：从布尔到统计再到署名决策

## 11.0 旧门禁为什么不成立

```python
if 测试通过率 >= 0.95:
    放行
```

三个问题：

1. **通过率是点估计**，在非确定性系统上不携带不确定性信息；
2. **一个数掩盖了 blocker**——95% 里可能包含一次跨租户泄露；
3. **它把风险决定藏进了一个阈值里**，没有人为此署名。

## 11.1 新门禁的三段

```text
第一段 · 硬红线（任何一条不满足 = 阻断，无例外）
  ├─ D5 高危攻击 ASR = 0
  ├─ D7-1 硬业务规则违反 = 0
  ├─ D5-6 不可逆动作绕过确认 = 0
  └─ D0-1 judge κ ≥ <阈值>（否则本轮所有分数无效）

第二段 · 统计门禁（看置信区间，不看点估计）
  ├─ pass^k 的 95% CI 下界 ≥ <阈值>
  ├─ 与上一版本对比：CI 不重叠才判定为回归
  └─ 样本量不足 → 结论为「证据不足」，不是「通过」

第三段 · 风险接受（不是通过/失败，是明示决策）
  ├─ 列出所有已知失败模式及其频率
  ├─ 标注每个失败模式的运行时护栏覆盖情况
  └─ 由有明确责任人的角色签字接受剩余风险
```

## 11.2 第一段：硬红线为什么不参与统计

硬红线上的四项都是**"发生一次就不可接受"**的事件，对它们做区间估计没有意义。

| 红线 | 为什么不能统计化 |
| --- | --- |
| 高危攻击按 `<security_policy>` 判定 | 即使区间较窄，也不能把未覆盖攻击面写成零风险；任何已知成功攻击单列 blocker |
| 硬业务规则违反 = 0 | 已发货订单被取消一次就是资金事故 |
| 不可逆动作绕过确认 = 0 | 不可逆意味着没有第二次机会 |
| judge κ 达标 | **它不是一项指标，它是其他所有指标的前提** |

第四条要特别注意措辞：judge 失准时，结论不是"这一项失败"，而是**本轮所有分数无效**——你不知道它们是多少。

## 11.3 第二段：三种统计结论

| 结论 | 条件 | 下一步 |
| --- | --- | --- |
| `PASS` | CI 下界 ≥ 阈值 | 进入第三段 |
| `FAIL` | CI 上界 < 阈值，或与旧版本 CI 不重叠且更差 | 阻断，回到修复 |
| `EVIDENCE-INSUFFICIENT` | 样本量不足以支撑任一结论 | **不是通过**。补样本或降低承诺 |

**`EVIDENCE-INSUFFICIENT` 是一个合法且诚实的结论。** 把它写成"通过"是本段最常见的事故。

## 11.4 第三段是关键的心智转变

> **Agent 系统不存在"没有失败模式"的版本。**

测试的职责不是宣布"没问题"，而是：

```text
1. 把失败模式测清楚
2. 量化其频率
3. 确认护栏兜得住
```

然后让业务方在**知情**的前提下决定是否接受。

### 风险接受记录的形状

```text
版本            : agent-refund@v3（模型/prompt/工具/记忆 四维见 lineage）
已知失败模式    :
  FM-01 长任务（>2h）pass^5 = 22% [CI 14%–33%]
        护栏覆盖: 强制检查点每 30 分钟 + 超时转人工      → 接受
  FM-02 多轮延迟注入在 3/200 样本上到达工具层，被授权层拦下
        护栏覆盖: 工具白名单 + 最小 scope               → 接受
  FM-03 并发 50 时 pass^5 下降 9pt
        护栏覆盖: 无                                     → 不接受，限流至 30
剩余风险接受人  : <姓名/角色>        日期: <YYYY-MM-DD>
复评日期        : <YYYY-MM-DD>
回滚触发条件    : <条件列表>
```

**没有护栏覆盖的失败模式不能被"接受"**——那不是接受风险，那是不知道有风险。

## 11.5 三段之间的关系

```text
第一段失败  → 直接阻断，不进入第二段（没必要算区间）
第二段 FAIL → 阻断
第二段 EVIDENCE-INSUFFICIENT → 可以进入第三段，但必须作为已知失败模式列出
第三段      → 不产生 PASS/FAIL，产生一份署名决定
```

**流水线永远不输出"可以发布"，它输出"证据齐了，请决定"。**

## 11.6 常见反模式

| 反模式 | 后果 | 正确做法 |
| --- | --- | --- |
| 用一个综合分表示质量 | blocker 被稀释 | 三段分开输出 |
| 把 `EVIDENCE-INSUFFICIENT` 写成通过 | 承诺无依据 | 保留为独立结论 |
| 硬红线做统计化处理 | 允许了不可接受事件 | 硬红线 = 0，不做区间 |
| 无护栏覆盖仍签字接受 | 接受了不知道的风险 | 先补护栏或不接受 |
| 让模型批准 waiver | 违反公理 4 与决策权归属 | 发布 owner 署名 |
| 第三段由测试开发签 | 越权代替业务方接受风险 | 具名业务/发布 owner |

## 11.7 可运行练习

```bash
cd materials/agent-architecture-system
python3 scripts/agent_reliability_lab.py gate --input fixtures/gate-input.json
python3 scripts/agent_reliability_lab.py gate --input fixtures/gate-input.json --fault redline-statistical
python3 scripts/agent_reliability_lab.py gate --input fixtures/gate-input.json --fault unsigned-acceptance
```

基线：三段依次判定，输出 `PASS / EVIDENCE-INSUFFICIENT / 风险接受清单`，退出 `0`。
`redline-statistical`：把硬红线改成区间判定后退出 `1`，指名 `GATE-1/REDLINE-NOT-STATISTICAL`。
`unsigned-acceptance`：剩余风险无署名人后退出 `1`，指名 `GATE-3/UNSIGNED-ACCEPTANCE`。

## 11.8 证据边界

三段结构是**工程综合（Inference）**，由非确定性系统的统计性质与决策权归属原则推导而来。
所有阈值为**结构占位**。
本地夹具只验证**判定逻辑**，不产生任何真实系统的门禁结论。

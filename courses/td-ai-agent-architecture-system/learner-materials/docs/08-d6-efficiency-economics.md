# 08 D6 效率经济层：成本是长尾，不是均值

## 8.0 给完全没接触过的人

传统接口性能看平均响应时间就大致够用。Agent 不行：**中位数很便宜，但失控案例能烧掉几个数量级**。

一个每次平均花 0.02 元的 Agent，可能有 0.5% 的任务因为进入循环花了 200 元。看均值你永远发现不了它。

## 8.1 四个维度

| 编号 | 维度 | 判据形状 |
| --- | --- | --- |
| D6-1 | 延迟与吞吐 | P95 首字 < `<阈值>`；P99 全流程 < `<阈值>` |
| D6-2 | **Token 与成本经济学** | 单任务成本 **CI 上界** ≤ 预算；成本 CV ≤ `<阈值>` |
| D6-3 | 并发与资源隔离 | 目标并发下 `pass^k` 下降 ≤ `<阈值>` |
| D6-4 | 可观测性与可复现 | `<trace_required_fields>`、`<capture_policy>` 与 `<replay_target>` 由场景配置；缺关键步骤则阻断归因 |

## 8.2 D6-2 成本作为一等指标

### 四条规则

1. **报成本的 P99，不报均值。** 均值会被长尾污染成一个既不代表典型也不代表最坏的数。
2. **设单任务 token 硬上限，并测试它真的会截断。** 配置了不等于会触发。
3. **跟踪成本–质量帕累托前沿**：换更便宜的模型，`pass^k` 掉多少？这是唯一能支撑选型的对照。
4. **评估基础设施自身成本要进预算**——通常占 Agent 运营成本的 **10–25%**（来源观测）。judge 调用、重复运行、trace 存储都不是免费的。

### 单位成功成本

```text
单位成功成本 = (模型费 + 工具费 + 人工复核费) / 成功完成的任务数
```

它能同时暴露**质量下降**（分母减小）和**成本上升**（分子增大）。单看 token 费用两者都看不出来。

**任何架构变更**（单 Agent → 多 Agent、换模型、加检索、加重试）都必须在**同预算、同任务集**下报告变更前后的单位成功成本。

### 重试的成本陷阱

增加重试能提高 `pass@k`，但会：

```text
成本   × 重试次数
延迟   × 重试次数（串行时）
副作用 × 重试次数（无幂等时）
pass^k 不变甚至更差（每次都对的概率没提高）
```

**用重试提高的 `pass@k` 不能写进可靠性承诺。**

## 8.3 D6-4 可复现性是一切的前提

**如果一条失败 trace 无法重放，就无法归因，也就无法修。**

trace 必须记录五要素：

```text
□ 模型版本 + temperature + 随机种子
□ 完整 prompt（含 system）
□ 工具清单快照（含每个工具的 description hash）   ← 最容易漏
□ 每次工具调用的输入与输出
□ 时间戳（尤其是行情类数据的获取时刻）           ← 高风险场景必需
```

第三项与 D5-2 直接相关：没有 description hash，你无法证明工具描述在运行时没被改过（rug-pull）。

## 8.4 D6-1 与 D6-3

| 检查 | 注意 |
| --- | --- |
| P95 首字 | Agent 的"首字"通常在多次工具调用之后，不等于 LLM 的 TTFT |
| P99 全流程 | 必须按任务类型分桶——只读查询与写操作混在一起没有意义 |
| 并发下 `pass^k` | **并发不只影响延迟，也影响正确性**（共享状态、限流重试、缓存命中差异） |
| 资源隔离 | 高危写任务不应与批量只读任务共享同一配额池 |

## 8.5 常见反模式

| 反模式 | 后果 | 正确做法 |
| --- | --- | --- |
| 只报平均延迟与 QPS | 长尾与失控循环被藏起来 | 报 P95/P99 与成本 P99 |
| 把提高预算当作修复 | 失控循环继续存在，只是更贵 | 修循环根因，保留硬上限 |
| 用重试提高的 pass@k 做承诺 | 承诺无法兑现 | 承诺基于 pass^k |
| trace 采样率过低 | 关键失败没记录 | 按风险配置 capture policy，任何已知高危漏记均单列 blocker |
| 缺少工具 description hash | 无法证明未被 rug-pull | 快照进 trace |
| 只读与写任务混在同一 workload | 结论不可用 | 按任务类型分桶 |

## 8.6 可运行练习

```bash
cd materials/agent-architecture-system
python3 scripts/agent_reliability_lab.py economics --input fixtures/cost-ledger.json
python3 scripts/agent_reliability_lab.py economics --input fixtures/cost-ledger.json --fault no-hard-budget
```

第一条输出 P95/P99、成本尾部、单位成功成本与预算截断验证并退出 `0`；
第二条移除硬预算后退出 `1`，指名 `D6-2/HARD-BUDGET`。

## 8.7 证据边界

"评估基础设施占运营成本 10–25%"是**来源观测**，不是你系统的预期值。
所有延迟与成本阈值必须由 workload profile、价格生效时间与 owner 配置，**不能跨环境搬运**。

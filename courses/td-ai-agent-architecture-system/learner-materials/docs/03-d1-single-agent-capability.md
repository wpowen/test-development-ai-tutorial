# 03 D1 单体能力层：从终局评分走到 span 级轨迹

## 3.0 给完全没接触过的人

传统测试问的是"最后答对了吗"。Agent 会走十几步：查订单、读政策、算金额、调工具、回复用户。**只看最后一句话，等于只看考试成绩不看解题过程**——学生可能蒙对了，也可能中途抄了不该抄的东西。

span 就是"解题过程里的一步"。D1-3 要求给每一步单独打标签。

## 3.1 五个维度

| 编号 | 维度 | 测什么 | 判据形状 | 关键提醒 |
| --- | --- | --- | --- | --- |
| D1-1 | 意图理解 | 意图分类正确性 | 高危意图零误判 | 交易场景买/卖/撤单方向误判 = P0 |
| D1-2 | 工具选择与参数 | 选对工具、参数构造正确 | 参数精确匹配要求 **高于** 工具选择正确率 | **参数错误比工具错误危险得多** |
| D1-3 | 轨迹质量（span 级） | 逐步打分 | 每步得分 + 步骤效率比 | 本层重点 |
| D1-4 | 记忆读写与检索 | 记忆召回、错误记忆 | 错误记忆率有上界 | 错误记忆会跨会话传播 |
| D1-5 | 规划与自我修正 | 计划可执行、错误后自纠 | 注入错误观测看能否回正 | 自纠能力不能靠"多试几次"冒充 |

### 为什么参数错误比工具错误危险

选错工具通常会立刻报错（工具不存在、参数不匹配、权限拒绝）；**参数错误会被成功执行**。

```text
选错工具:  调用 get_user 而不是 get_order  → 立刻 404，容易发现
参数错误:  调用 refund(amount=1000.00)     → 成功执行，10.00 变成 1000.00
           而本应是 refund(amount=10.00)
```

因此 D1-2 的参数精确匹配阈值必须**严于**工具选择正确率。

## 3.2 D1-3 轨迹评估方案：四类 span 标签

对每条 trace 的每个 span 打四类标签：

| 标签 | 判定内容 | 取值 |
| --- | --- | --- |
| **工具选择** | 该调这个工具吗 | 正确 / 多余 / 遗漏 / 错误 |
| **参数构造** | 参数对吗 | 正确 / 部分正确 / 错误 |
| **观测利用** | 工具返回被正确使用了吗 | 正确利用 / 忽略 / 曲解 |
| **步骤必要性** | 这一步推进任务了吗 | 有效 / 冗余 |

### 三个派生指标

```text
步骤效率比 = 最优步数 / 实际步数
             ↑ 低于 1 说明有冗余步骤；接近 0 说明在原地打转

首错位置分布（First Error Position）
             ↑ 失败集中在第几步 —— 直接定位薄弱环节
               例：12 次失败中 9 次首错在 step3 → 问题在"读政策"这一步，不是模型笨

无效循环率 = 同一工具连续调用 ≥ 3 次且参数近似 的轨迹占比
             ↑ 这是成本失控和 11 天死循环的早期信号
```

**首错位置分布是本层最有行动价值的产出。** 一条"成功率 62%"的报告不能指导任何修复；一条"9/12 的失败首错在 step3 的政策检索"可以。

## 3.3 三层 Oracle 必须分别判定

| 层 | 判断 | 典型失败 | 禁止 |
| --- | --- | --- | --- |
| **Outcome** | 业务最终状态是否正确 | 结果对但过程越权 | 用它抵消 step 层失败 |
| **Step** | 每次调用的工具/参数/权限/前置是否合法 | 调用了禁止工具 | 用总分吞掉 |
| **Trajectory** | 状态、重试、Handoff、终止原因是否可接受 | 死循环、预算耗尽 | 只看最后一步 |

**不要把一条黄金轨迹当唯一正确答案**——那会惩罚合法替代路径。正确做法是写：

```text
不变量        : refund_count <= 1
禁止副作用    : 未验证身份前不得调用 refund_order
必要检查点    : 必须先 get_order 再判断 shipment_status
允许的替代路径: {查订单→读政策→转人工} 与 {读政策→查订单→转人工} 均合法
```

只有强流程约束场景（如合规要求的固定审批顺序）才要求精确顺序。

## 3.4 可复制的 span 台账格式

```jsonl
{"trace_id":"t-001","span":1,"tool":"get_order","params":{"order_id":"O-77"},"tool_choice":"正确","param_build":"正确","observation_use":"正确利用","necessity":"有效","authorized":true}
{"trace_id":"t-001","span":2,"tool":"search_policy","params":{"topic":"refund"},"tool_choice":"正确","param_build":"正确","observation_use":"曲解","necessity":"有效","authorized":true}
{"trace_id":"t-001","span":3,"tool":"refund_order","params":{"amount":10.0},"tool_choice":"错误","param_build":"正确","observation_use":"忽略","necessity":"有效","authorized":false}
```

从这三行可以直接读出：首错位置 = span2（观测曲解），越权发生在 span3，最终文本正确与否**不影响**这两个结论。

## 3.5 常见反模式

| 反模式 | 后果 | 正确做法 |
| --- | --- | --- |
| 只评最终输出 | 漏掉约九成中途失败 | 三层分别判定 |
| 用唯一黄金轨迹比对 | 错杀合法替代路径 | 写不变量 + 禁止副作用 |
| 把"步骤多"当成"更认真" | 掩盖冗余与循环 | 用步骤效率比 |
| 参数与工具用同一阈值 | 放过更危险的参数错误 | 参数阈值更严 |
| trace 采样率过低 | 关键失败没记录，无法归因 | 按风险配置 capture policy，任何已知高危漏记均单列 blocker |

## 3.7 证据边界

span 四标签与三个派生指标的划分方式是**跨来源工程综合（Inference）**，不是任何标准规定的固定集合。
步骤效率比、首错位置、无效循环率**必须声明分母与任务范围**，不能跨系统直接比较。

# 02 D0 评估可信层：先测 judge，再相信分数

> **这一层不测 Agent，测你的测量系统。**
> 如果只能做一件事，做这一件。你现在所有评估数字的准确性上限，都取决于那个 judge 有多准——而这件事大概率还没有被量化过。

## 2.0 给完全没接触过的人

一句话：你用一个模型给另一个模型的答案打分，但**从来没人检查过打分的那个模型准不准**。

打个比方：你请了一位阅卷老师批 1000 份卷子，然后拿着分数做升学决策。但你从没让这位老师和另外两位老师批同一批卷子对过答案，也不知道他是不是"字写得漂亮就多给分"。这份成绩单的可信度上限，就是这位老师的水平——而你不知道那是多少。

本层要做的，就是**先给阅卷老师出一套有标准答案的卷子**。

## 2.1 四个维度

| 编号 | 维度 | 测什么 | 频率 |
| --- | --- | --- | --- |
| D0-1 | Judge 校准与元评估 | judge 与人类一致性、位置偏置、冗长偏置、自偏好 | 每月 + 换模型时 |
| D0-2 | 评估集卫生 | 训练污染、场景漂移、与生产分布的代表性 | 每季度 |
| D0-3 | 指标构念效度 | 指标是否真的测了它声称测的东西 | 每季度 |
| D0-4 | 人审闭环与标注一致性 | 标注者间一致性、争议样本仲裁 | 持续 |

## 2.2 D0-1 详细方案（全案最关键的七步）

### 第 1 步：建金标集

- 规模：`<200–300 条>`（占位；按你的任务多样性决定）
- **3 名标注员独立打分**
- **κ < 阈值的条目说明评分标准本身有歧义 —— 先改 rubric，不要急着改 judge**

这一步最常见的错误是跳过人人一致性，直接比较"模型 vs 一名标注员"。那样你分不清是 judge 错了还是人本身就不一致。

### 第 2 步：judge 与 generator 必须不同模型族

规避自偏好偏置。同一模型族的 judge 会系统性偏爱同族生成的表达方式，这不是能力，是家族口音。

### 第 3 步：成对比较必须双向跑

A/B 和 B/A 各跑一次。**结果不一致的判为无效样本**，单独统计位置偏置。

```text
样本 S：候选甲 vs 候选乙
  第一次：[甲, 乙] → judge 选甲
  第二次：[乙, 甲] → judge 选甲   ✓ 位置稳定
  第二次：[乙, 甲] → judge 选乙   ✗ 位置偏置，该样本无效
```

### 第 4 步：锁版本 + 定期重校准

冻结模型版本换来的是**陈旧风险**，所以要定期重跑金标集追踪 κ 漂移。

**κ 跌破阈值 → judge 停用，回退人审。** 这是一条硬规则，不是建议。

> 实测案例：供应商在同一模型名下静默更新，κ 从 0.72 掉到 0.58，团队毫无察觉。

### 第 5 步：分层 judge 策略

| 场景 | judge | 特性 | 作用 |
| --- | --- | --- | --- |
| CI 门禁 | 前沿模型 | 慢、贵、准 | 校准锚点 |
| 生产在线采样 | 小模型 | 快、便宜 | 用前沿 judge + 人工标注校准 |

小模型 judge 不是"降级方案"，它是被前沿 judge 校准过的**受控代理**。没有校准链的小模型 judge 只是便宜的噪声。

### 第 6 步：混合范式（Hybrid Norm）

```text
可验证的部分  → 确定性断言 / 单元测试   回答「做对了吗」
开放式的部分  → LLM rubric              回答「做得好吗」
```

**不要用 rubric 去测本可以用断言测的东西。** 金额、状态、权限、引用存在性都能用断言测，用 rubric 测它们既贵又不准。

### 第 7 步：产出 Judge Card

**judge 换版本 = 一次需要走变更评审的发布。**

```text
┌─ Judge Card ───────────────────────────────────────┐
│ judge_id        : judge-refund-v3                  │
│ 模型与版本      : <provider>/<model>@<version>      │
│ temperature     : <值>                             │
│ rubric 全文     : <内联或指向版本化文件>            │
│ 校准日期        : <YYYY-MM-DD>                     │
│ 金标集          : <id> / <样本量> / <标注员>        │
│ Cohen's κ       : <值>（与人类）                   │
│ 标注者间 κ      : <值>（人与人）                   │
│ Spearman        : <值>                             │
│ 位置偏置        : 交换一致率 <值>                   │
│ 冗长偏置        : 长度分组分差 <值>                 │
│ 自偏好          : 同族/异族胜率差 <值>              │
│ 允许自动评分的范围: <切片列表>                      │
│ 必须人工的范围  : <切片列表>                        │
│ 停用条件        : κ < <阈值> 或换版本               │
│ owner           : <姓名>                           │
└────────────────────────────────────────────────────┘
```

模板：`materials/agent-architecture-system/templates/judge-card.md`

## 2.3 三类偏置探针的构造方法

| 偏置 | 构造 | 期望 | 失败信号 |
| --- | --- | --- | --- |
| **位置偏置** | 同一对候选，交换顺序各跑一次 | 判定不变 | 顺序一变胜负就变 |
| **冗长偏置** | 在同事实答案上加入无关的礼貌性/解释性文字 | 分数不上升 | 长的那个总赢 |
| **自偏好** | 用同族与异族模型各生成一组等质量答案 | 胜率相当 | 同族显著更高 |

**追加一类：事实错误穿透探针。** 构造一批"表达流畅但引用过期政策"的答案，看 judge 会不会因为语言好而放过事实错误。这一类必须由确定性规则（L4）兜底，不能交给 judge。

## 2.4 D0-2 评估集卫生

| 检查 | 怎么做 | 失败处置 |
| --- | --- | --- |
| 训练污染 | 公开数据集核对可能已进训练；自建集检查是否被写进 Prompt 示例 | 重建集合 |
| 场景漂移 | 评估集分布 vs 生产分布对比 | 补样本 |
| 代表性 | 高风险切片是否被覆盖 | 补切片 |
| holdout 卫生 | 开封次数计数 | 超约定即作废重建 |

## 2.5 D0-3 指标构念效度

**"指标是否真的测了它声称测的东西"** —— 这是最容易被跳过、也最容易造成长期误导的一维。

典型失效：

```text
指标名: 「回答有用性得分」
实际测: judge 对措辞礼貌程度的偏好
后果  : 团队优化了半年措辞，业务转化率没动
```

检查方法：把指标与**已知的业务结果**对照（转化、工单再开率、人工介入率）。相关性长期低于约定值，说明这个指标是自娱自乐，应该下线而不是继续优化。

## 2.6 D0-4 人审闭环

- 标注者间 κ 是**下限**：judge 不可能比人与人之间更一致。
- 争议样本必须有**仲裁流程**与仲裁人，不能取平均了事。
- 争议率本身是信号：争议率高说明 rubric 有歧义。

## 2.7 常见反模式

| 反模式 | 为什么错 | 正确做法 |
| --- | --- | --- |
| 只比较 judge 与一名标注员 | 分不清 judge 错还是人不一致 | 先测人人一致性 |
| judge 与 generator 同一模型 | 自偏好污染 | 换模型族 |
| 成对比较只跑一个方向 | 位置偏置被计入能力 | 双向跑，不一致判无效 |
| 换 judge 后沿用旧阈值 | 校准失效 | 重新校准并出新卡片 |
| 用 rubric 测金额与权限 | 贵且不准 | 用确定性断言 |
| κ 掉了但继续用 | 所有下游数字失效 | 停用，回退人审 |
| 递归让模型评模型的评估 | 元评估漂移，内部自洽但脱离现实 | 定期用人工金标锚定 |

## 2.8 与三段式门禁的关系

D0-1 是**硬红线**的一部分：

```text
第一段 · 硬红线
  └─ D0-1 judge κ ≥ <阈值>（否则本轮所有分数无效）
```

注意措辞：不是"这一项失败"，而是**本轮所有分数无效**。judge 失准时，D1–D7 的数字不是"偏低"，而是"不知道是多少"。

## 2.9 可运行练习

```bash
cd materials/agent-architecture-system
python3 scripts/agent_reliability_lab.py judge --input fixtures/judge-calibration.json
python3 scripts/agent_reliability_lab.py judge --input fixtures/judge-calibration.json --fault position-bias
```

第一条应输出 κ、位置一致率、冗长与自偏好探针结果并退出 `0`；
第二条注入位置偏置后应退出 `1`，并指名 `D0-1/POSITION-STABILITY` 失败。

## 2.10 本层的证据边界

- 上述方法来自公开的 judge 可信度研究与评测实践综合（**Inference**）。
- 所有 κ、一致率、样本量数值为**结构占位**，必须按你的任务与标注资源实测设定。
- 本层的夹具只证明**计算与判定逻辑可运行**；你的 judge 与你的领域专家的真实 κ 为 `UNKNOWN`，必须自己测。

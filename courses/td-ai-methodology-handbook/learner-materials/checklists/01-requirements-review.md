# 检查单 01：需求评审（S1–S2）

> 用法：评审会上逐条打勾。任一"否"即不得进入用例设计。

## 依据完整性
- [ ] 所有输入文件已登记版本、owner、hash、敏感级
- [ ] 网页类来源保存了访问日期或提交版本
- [ ] AI 侧依据（模型、Prompt、索引、工具）也已冻结
- [ ] 每段内容有稳定 `source_ref`，不随文档重排变化
- [ ] 来源优先级规则已书面确认，非口头默契

## 规则可测性
- [ ] 每条规则有明确 actor、前置、触发、可观察结果
- [ ] 每条不变量可判定（不是"系统应稳定"这类不可判定表述）
- [ ] 每条异常有触发条件与错误语义，不只有错误码
- [ ] 副作用已列出，且说明是否幂等
- [ ] 非功能要求有具体度量对象（不是"性能好"）

## 未知与冲突
- [ ] `unknowns` 非空（真实需求不可能全部明确；为空说明没认真做）
- [ ] 每条 `unknown` 指定了需谁确认
- [ ] 冲突已登记且 `status=BLOCKED`，指名双方 source_ref
- [ ] 冲突已指定升级责任人
- [ ] 没有出现"综合判断后采用更合理的规则"

## 权限与安全
- [ ] 已确认哪些决定不能由 AI 作出（对照方法论 01 章 1.3 表）
- [ ] 提取 Prompt 中写入了权限声明与失败语义
- [ ] 输入中无生产密钥、真实支付账号、未脱敏个人信息

## 两道门禁
- [ ] 结构门禁 `PASS_SCHEMA` 已自动执行并留痕
- [ ] 语义门禁 `PASS_SEMANTIC` 已由领域 owner 署名
- [ ] 两者**未被合并**成一个"通过"

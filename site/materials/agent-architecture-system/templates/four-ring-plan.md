# 四环执行计划

每个环必须声明五件事，缺任一项该环结果不得作为发布证据。

## 环 1 · 离线 CI

```
触发        : 每次提交
时长预算    : <≤ 10 min>
覆盖维度    : D1 核心子集、D4-3、D5 静态规则
population  : <确定性夹具集，n=?>
统计方法    : 布尔（确定性）
owner       : <姓名>
hard block  : <哪些条件硬阻断合并>
rollback    : <失败时回滚什么>
当前状态    : RUN / NOT_RUN
```

## 环 2 · 沙箱回放

```
触发        : 每日 / PR 合并
时长预算    : <≤ 2 h>
覆盖维度    : D1 全量、D2、D4 全量、D5 全量
population  : <回放集 id，n=?，来源与刷新频率>
统计方法    : pass^k + Wilson 区间，聚类单位 = 任务
owner       : <姓名>
hard block  : pass^k CI 下界 < 阈值 → 阻断发布
rollback    : 四维成组（模型/prompt/工具/记忆）
当前状态    : RUN / NOT_RUN
```

## 环 3 · 影子 + 灰度

```
触发        : 每次发布
时长        : <3–7 天，需覆盖一个完整业务周期>
覆盖维度    : D3、D6、D7-1
population  : 真实流量 <采样比例>
生效性      : 新版结果【不返回用户】【不执行动作】
零副作用断言: <怎么验证新版确实没生效>
差异判定    : 输出不一致 ≠ 错误，先用 Oracle 判定差异性质
统计方法    : 分布对比，CI 不重叠才判回归
owner       : <姓名>
hard block  : <软门禁，看在线指标>
rollback    : <分钟级 / 人工>
当前状态    : RUN / NOT_RUN
```

## 环 4 · 在线持续评估

```
触发        : 7×24
采样        : 常规 <1–10%>，高危动作 100%
评估器      : 必须与开发阶段相同（否则线上分数不可比）
judge 校准  : 小模型 judge 必须被前沿 judge + 人工锚定
覆盖维度    : 全部
统计方法    : 漂移检测（相对发布基线）
owner       : <姓名>
hard block  : 告警 + 自动回滚触发条件
rollback    : <分钟级、自动>
当前状态    : RUN / NOT_RUN
```

## 环间纪律

| 环 | 能证明 | **不能**证明 |
| --- | --- | --- |
| 环 1 | 确定性规则与静态契约成立 | 模型行为可靠 |
| 环 2 | 在固定回放集上分布达标 | 在真实流量分布上达标 |
| 环 3 | 在真实流量上分布可比 | 生效后的业务结果 |
| 环 4 | 生产上正在发生什么 | 未来不会漂移 |

**跨环升级必须有新的输入、新的 owner 和回滚证据。** 把环 2 的绿色写成"生产可用"是成熟度冒充。

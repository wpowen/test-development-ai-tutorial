# 06 D4 鲁棒可靠层：从「一个数」到「一个分布」

> 这是整套架构中**范式重构**最彻底的一层。其他层是加维度，这一层是换判定方式。

## 6.0 给完全没接触过的人

传统测试：跑一遍，绿了就是通过。

Agent：跑一遍绿了，再跑一遍可能红。**同一个输入返回不同结果，在传统软件里是 bug，在 LLM 驱动的 Agent 里是正常行为。**

所以"通过"这个词在这里没有意义。你必须回答两个不同的问题：

```text
问题 A：它「能不能」做对？        → pass@k
问题 B：它「能不能每次都」做对？  → pass^k    ← 你对用户的承诺是这个
```

这两个数可以差得极远。

## 6.1 五个维度

| 编号 | 维度 | 判据形状 | 手法 |
| --- | --- | --- | --- |
| D4-1 | 可靠性分布 | `pass^k` 的 `<confidence_interval>` 下界 ≥ `<threshold>`；CV ≤ `<threshold>` | 运行次数由风险与估计目标配置 |
| D4-2 | 长时程降级 | 50% 成功视界 ≥ 业务需求时长 | 按任务时长分桶画衰减曲线 |
| D4-3 | Prompt/输入稳定性 | 语义等价改写一致率 ≥ `<阈值>` | 每条用例生成 5 个改写变体 |
| D4-4 | 异常与自恢复 | 异常场景恢复率 ≥ `<阈值>` | 混沌注入 |
| D4-5 | 统计回归 | **非重叠 CI 才算真回归** | 新旧版本分布对比 |

## 6.2 D4-1：两个指标的精确定义

设任务集 `T = {t₁ … tₙ}`，每个任务独立重复 `k` 次，`sᵢ` 为任务 `tᵢ` 成功的次数。

### pass@k —— 至少一次成功

**经验口径**（直接从观测算，本手册与配套 lab 采用这一口径）：

```text
pass@k = |{ tᵢ : sᵢ ≥ 1 }| / n
```

**解析口径**（已知单次成功率 `p` 时的期望值）：

```text
pass@k = 1 − (1 − p)^k
```

> ⚠ 两个口径经常被混用。报告中必须写明用的是哪一个，否则数字不可比。

### pass^k —— 每次都成功

```text
pass^k = |{ tᵢ : sᵢ = k }| / n
```

解析口径为 `p^k`。

### 为什么差距会很大

```text
单次成功率 p = 0.9

pass@5  = 1 − 0.1⁵ ≈ 99.99%      看起来非常可靠
pass^5  = 0.9⁵     ≈ 59.0%       实际上五次里有四成会遇到至少一次失败
```

用户执行五次任务，有 41% 的概率至少踩一次坑。**你承诺的是 59%，不是 99.99%。**

### 一个具体的教学例子

```text
任务 T 跑 5 次，结果：成功 成功 失败 成功 成功

旧写法: 通过率 4/5 = 80%  →  ✅ 通过

新写法:
  pass@1 = 80%    （能不能做到）
  pass^5 = 0%     （能不能每次都做到）  ← 上线看这个
  首错位置 = step3                       ← 改进看这个
```

同一次运行，三个数字回答三个完全不同的问题。**只报第一个就是在隐藏后两个。**

## 6.3 k 怎么选

| 任务优先级 | k（占位） | 理由 |
| --- | ---: | --- |
| P0（不可逆 / 资金 / 权限） | 10 | 需要更窄的区间支撑高阈值 |
| P1（核心业务） | 5 | 平衡成本与结论强度 |
| P2（辅助功能） | 3 | 能看出明显不稳定即可 |

**k 越小，`pass^k` 越乐观。** k=1 时 `pass^k = pass@1`，两个指标退化成同一个数——这就是旧口径的问题所在。

## 6.4 门禁改写：从点估计到区间

```text
旧: if pass_rate >= 0.95: 放行
新: if lower_bound(pass^k, confidence=0.95) >= threshold: 放行
    elif sample_size_insufficient: 结论 = EVIDENCE-INSUFFICIENT   ← 不是「通过」
    else: 阻断
```

### 三个必须显式处理的情况

| 情况 | 错误做法 | 正确做法 |
| --- | --- | --- |
| 样本量不足 | 按点估计放行 | 输出 `EVIDENCE-INSUFFICIENT` |
| 区间很宽但下界勉强达标 | 报告"达标" | 同时报告区间宽度与样本量理由 |
| 某切片样本为 0 | 从总分中忽略 | 该切片单独标 `NOT_MEASURED` |

**"证据不足"是一个合法结论，而且比"通过"诚实。**

### 区间怎么算

本手册与配套 lab 用 **Wilson score interval**（小样本下比正态近似稳健）：

```text
中心 = (x + z²/2) / (n + z²)
半宽 = z·√( x(n−x)/n + z²/4 ) / (n + z²)
其中 x = 成功任务数, n = 任务总数, z = 1.96（95%）
```

> ⚠ **重复运行不是完全独立样本。** 同一任务的 k 次运行高度相关；直接把 `n×k` 当样本量会严重低估不确定性。正确做法是**以任务为聚类单位**：先按任务聚合成 0/1（是否 k 次全对），再对任务数做区间估计。配套 lab 采用这一做法。

## 6.5 D4-2 长时程降级

按任务预期时长分桶，每桶单独计算 `pass^k`：

| 时长桶 | pass@1 | pass^5 | 结论 |
| --- | --- | --- | --- |
| < 5 min | | | |
| 5–30 min | | | |
| 30 min–2 h | | | |
| > 2 h | | | |

产出的结论形如：

> "本 Agent 在 30 分钟内任务 `pass^5 = 85%`，超过 2 小时降至 22%。"

**这句话可以直接转化成两个产品决定**：

1. **自主时长上限** —— 超过阈值必须切分任务或转人工；
2. **强制检查点间隔** —— 每隔多久必须有一次人工或规则校验。

这是本层最有商业价值的产出：它把一个技术指标变成了一条产品规则。

## 6.6 D4-3 输入稳定性

每条用例生成 5 个**语义等价改写**，检查结论是否一致。

```text
原句: "帮我取消订单 O-77"
改写: "O-77 这单我不要了"
      "请把 O-77 退掉"
      "cancel order O-77"
      "订单号 O-77，申请取消"
      "我想取消一下 O-77 这个订单，谢谢"
```

**改写必须由人确认语义等价**，不能由生成改写的同一个模型自己判定等价——那是公理 4 的违反。

## 6.7 D4-5 统计回归：什么才算真的变差

```text
✗ 错误: 新版本 82%，旧版本 85%，下降 3 个点 → 判定回归
✓ 正确: 新版本 [76%, 88%]，旧版本 [79%, 91%]  → 区间重叠 → 无结论
        新版本 [70%, 79%]，旧版本 [83%, 92%]  → 区间不重叠 → 判定回归
```

**非重叠 CI 才算真回归。** 点估计的涨跌在非确定性系统上大多是噪声。

⚠ 反过来也要注意：**"区间不重叠"是一个保守的充分条件，不是唯一正确的统计原则。** 更严谨的做法是对配对/聚类数据做显著性检验。本手册采用区间法是因为它容易解释且不易被误用，但不应把它写成"唯一统计原则"。

## 6.8 温度与随机性

```text
□ 评估必须固定 temperature 并记录在 Run Receipt
□ 同时跑一组 temperature > 0 的变异性探针
□ temperature = 0 不等于完全确定 —— 仍需重复运行
```

第三条最常被误解。即使 temperature=0，批处理、缓存、硬件差异仍可能造成不同输出。

## 6.9 常见反模式

| 反模式 | 后果 | 正确做法 |
| --- | --- | --- |
| 只报 `pass@k` | 隐藏一致性崩塌 | 两个都报，承诺基于 `pass^k` |
| 混用经验口径与解析口径 | 数字不可比 | 报告中写明口径 |
| 把 `n×k` 当独立样本 | 严重低估不确定性 | 以任务为聚类单位 |
| 样本不足时按点估计放行 | 结论不成立 | 输出 `EVIDENCE-INSUFFICIENT` |
| 删除失败 run 让分布好看 | 数据造假 | 保留全部 raw run |
| 用重试提高的 `pass@k` 做承诺 | 成本爆炸且承诺无法兑现 | 承诺基于 `pass^k` |
| 只测短任务 | horizon 衰减看不出 | 按时长分桶 |
| 改写等价性由生成模型自判 | 违反公理 4 | 人工确认等价 |

## 6.11 Metric Card：这一层的交付物

任何 `pass^k` 结论都必须附一张卡片，否则不可复用：

```text
指标名        : pass^5（每次都成功）
口径          : 经验口径（|{sᵢ = k}| / n）
分子 / 分母   : <成功任务数> / <任务总数>
k             : 5
状态重置规则  : 每次 run 前重置到 <快照 id>
区间方法      : Wilson，聚类单位 = 任务
样本量理由    : <为什么这个 n 足够/不足够>
时长桶        : <桶定义>
切片          : <切片列表，含 blocker 标记>
版本          : 模型/prompt/工具/记忆 四维
owner         : <姓名>
失败动作      : <阻断 / 降级 / 转人工>
```

模板：`materials/agent-architecture-system/templates/reliability-metric-card.md`

## 6.12 证据边界

τ-bench 的 `pass@1 = 61% / pass^8 = 25%`、Claw-Eval 的 `Pass^3` 下跌 24 个百分点，是**来源观测**，用于证明"两个口径可以差得极远"，**不是你系统的预期值**。
k 的取值、CV 与百分比阈值均为**结构占位**。
Wilson 区间与任务聚类是本手册的**工程选择（Inference）**，不是唯一正确方法；更严谨的配对检验可以替代它。

# 准入准出准则

> 准出不是"用例都跑完了"，而是"约定深度的风险已被覆盖，剩余风险已被具名接受"。

## 1. 各阶段准入准出

| 阶段 | 准入 | 准出 |
| --- | --- | --- |
| S1 依据冻结 | 需求进入评审状态 | 文件可访问、版本唯一、坐标稳定、优先级规则已确认、敏感数据已处理、冲突已 BLOCKED |
| S2 需求契约 | S1 准出通过 | 每条规则有 source_ref 或明确 UNKNOWN；结构与语义分两道门禁并分别留痕 |
| S3 技术契约 | S2 准出通过 | 需求与组件/接口/状态/观察点双向可追；幂等与回滚有 owner |
| S4 风险与策略 | S3 准出通过 | 每条高风险有层级/方法/Oracle；不可行组合与残余风险已具名接受 |
| S5 Oracle | S4 准出通过 | 关键条件 Oracle 独立于被测实现；L5 未放行任何 blocker；无 Oracle 项已 BLOCKED |
| S6 用例与数据 | S5 准出通过 | 用例可追溯到 risk 与 Oracle；生成用例已过变异验证；holdout 已封存 |
| S7 环境与自动化 | S6 准出通过 | 环境可重建可回收有 owner；每个自动化用例满足五条准入门槛 |
| S8 执行与归因 | S7 准出通过 | lineage 完整；0/1/0 三段齐备；失败已定位到层或标 UNKNOWN 升级 |
| S9 发布 | S8 准出通过 | 见下表 |

## 2. 自动化用例的合并门槛（S7）

- [ ] 在预埋缺陷上稳定变红（≥3 次连续）
- [ ] 在干净基线上稳定变绿（≥3 次连续）
- [ ] 失败信息足以定位到层
- [ ] 运行时间在所属层级预算内
- [ ] 不依赖执行顺序、不依赖上次残留状态

## 4. 发布前必须能回答的七个问题

1. 这个版本相对上一个版本，只改变了什么？
2. 已知坏版本能否被当前门禁稳定拦下？证据在哪？
3. 高风险切片上，失败率的**区间**是多少？
4. 出问题时多久能发现、多久能回滚？
5. 哪些风险明知没测？谁签字接受？
6. 成本与延迟变化是多少？
7. 生产上用哪个信号判断"确实没问题"？

## 5. fail-closed 声明

门禁执行失败（脚本异常、环境未就绪、超时）**等同于不通过**，不得视为跳过。
